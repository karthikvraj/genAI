# Contributing

Start with a small reproducible failure case. Include the project, input (synthetic or approved), Python/dependency versions, observed output and expected behavior. Run `python -m pytest` before proposing a change.

Separate fitting, calibration and evaluation data. Compare against a named baseline. Keep negative results and counterexamples. Do not claim real-world improvements from the bundled synthetic examples. Do not add automatic infrastructure execution or silently send evidence to external APIs.

Use descriptive commits reflecting actual work. Do not backdate activity, manufacture stars/downloads, or invent adoption or performance claims. Attribute external code, datasets and model licenses. The initial implementation was developed with AI assistance.
